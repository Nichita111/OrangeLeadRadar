# Update Log

## 2026-09-25

* **Update**: Jev is served by OpenRouter's Decisions API with the OpenRouter key (`JEV_MODEL`, `JEV_DECISIONS_URL` replace `JEV_API_KEY`, `JEV_BASE_URL` and `JEV_PRICE_EUR_PER_CALL`), so `AC-23` verifies `S-SIG-04` inside the release gate and `S-SIG-10` keeps only Jev classifying under an exhausted budget; `operational_complexity` levels are defined by countries and business units; an import that changes an attribute rescores the account; a finding of a `CHOICE` question records its `option_key`, shown on Account detail.
* **Update**: The LLM provider is OpenRouter instead of Anthropic ([ADR-15](/architecture/adrs/adr-15-openrouter-as-the-llm-provider.md)): `OPENROUTER_API_KEY` and `OPENROUTER_BASE_URL` replace `ANTHROPIC_API_KEY`, the model keys hold OpenRouter model ids with no default, a call's cost is OpenRouter's reported `usage.cost` so `LLM_PRICES_EUR_PER_MTOK` is removed, and the audit `provider` value `ANTHROPIC` becomes `OPENROUTER`.
* **Update**: The Jev adapter is split into `B-38` and `S-SIG-10` (P1, verified by `AC-23` and the new `AC-70`), so the release gate no longer needs a Jev key, and `AC-27` tests the budget with the LLM adapter; the seed imports the accounts from the [demo account file](/architecture/overview.md#demo-dataset) with their careers, newsroom and report addresses, size and complexity, `AccountImportRow` gains `operational_complexity`, and `AC-10` expects the seeded accounts as updated; replay reads the clock from `CLOCK_FILE`; an inactive or new question counts only through an activated scoring version; only an Admin cancels reclassification, rescore and quality-check runs; `outreach_draft` `contact_id` is `ON DELETE SET NULL` and `classification` `strength` is null while pending; quotes are matched with typographic characters normalised and stored as the passage writes them; the Budget guard covers the LLM classifier adapter and names `LLM_PRICES_EUR_PER_MTOK`.
* **Update**: By owner decision contacts are entered by people only (the `contact` `origin` column is removed, [ADR-10](/architecture/adrs/adr-10-minimal-contact-data.md)); scheduled refresh (`B-15`), source detection (`B-36`), profile enrichment (`B-37`) and the moderated walkthrough (`N-13`, `AC-68`) are P1, with `AC-69` split from `AC-11`; a parent's view never combines subsidiaries' signals, Scoring settings stay Admin-only, and the Labelling screen offers no translation.
* **Update**: [Document conventions](/guidelines/documents/common.md#tooling) state the checker's cross-document rules — cited identifiers, numbering, priority inheritance, the release gate and tags — and every file's `tags` now equal the features whose reading order links it.
* **Update**: The bundle is created for spec-driven development of LeadRadar from the [challenge brief](/reference/challenge-brief.md) and [Annex 1](/reference/annex-1-participant-reference-pack.md): requirements (`RULE-01`–`RULE-10`, `B-01`–`B-35`, `SC-A`–`SC-D`, `S-` and `N-` rows with flows and entities, `AC-01`–`AC-67`), the kernel (SQL store, rules, interfaces `API-01`–`API-70`, overview with the demo dataset), the api, worker and frontend services, eight features with flows `FL-01`–`FL-21`, `ADR-01`–`ADR-14`, guidelines, the generated traceability matrix and the checker.
